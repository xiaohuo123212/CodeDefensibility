# 覆盖边界（scope）：识别七类，只判四类

> 本文档是本引擎「敢说什么、不敢说什么」的唯一书面口径。所有报告、答辩与回执统计都必须与本文一致；
> `tests/test_scope_doc.py` 会读取本文件文本，校验表格里的类型集合与 `gap_engine.schema.is_judgeable` 完全对齐。

## 七类条目

引擎从 README / 需求文档里识别七类可被对账的表述，不区分说话人（仓库自述与外部需求共用同一模型）。

| `ClaimType` 值 | 中文名 | 典型表述 |
| --- | --- | --- |
| `performance` | 性能 | 接口响应快，单机可支撑上万请求 |
| `concurrency` | 并发 | 支持 500 并发用户 |
| `feature` | 功能 | 支持 Excel 导出 |
| `testing` | 测试 | 测试覆盖率 80% |
| `security` | 安全 | 所有接口均做了鉴权与输入校验 |
| `architecture` | 架构 | 采用微服务架构，模块解耦 |
| `scale` | 规模 | 代码量 5 万行，覆盖 10 个业务线 |

## 判定域（下结论的四类）

这四类存在固定抽取路径，断言能落到具体 `file:line` 或留下可复现的搜索轨迹，因此可以给出
`supported` / `contradicted` / `no_evidence` 三态结论。

| `ClaimType` 值 | 中文名 | 为什么可以下结论 |
| --- | --- | --- |
| `performance` | 性能 | 压测脚本、benchmark 报告与性能相关配置都能定位到文件与行 |
| `concurrency` | 并发 | 线程/进程/worker 配置与压测文件的存在性可枚举，缺失本身即可反驳 |
| `feature` | 功能 | 路由、函数与第三方库调用构成确定的代码路径，能看到或看不到 |
| `testing` | 测试 | 测试文件、用例函数与覆盖率配置/报告都是可清点的静态事实 |

## 不判定域（识别但不判的三类）

这三类照样识别、照样计入覆盖率统计，但**不下结论**：没有固定抽取路径，任何结论都不可复现。
它们不进 `supported` / `contradicted` 的分子，也不进「对/错」比率的分子。

| `ClaimType` 值 | 为什么不下结论 | 要下结论还缺什么 |
| --- | --- | --- |
| `security` | 「安全」是属性而不是事实；仓库里能看到鉴权/校验代码的存在，却无法机械推出「所有入口都被覆盖」，也无法证明不存在漏洞 | 一份可执行的扫描口径（指定 SAST 规则集与扫描范围）+ 「每个路由都必须经过鉴权装饰器」这类可落到 `file:line` 的断言模板 |
| `architecture` | 架构是设计意图的叙述；代码只能反映目录与依赖形状，「微服务」「解耦」没有唯一抽取路径，同一份代码可被读成两种架构 | 把架构主张改写成可度量的结构约束（如「服务数 = N」「禁止跨层 import」），并配套依赖图抽取规则 |
| `scale` | 规模数字随统计口径剧烈变化（含/不含测试、注释与空行差异可达数倍），单个数字无法证伪 | 固定的统计口径（文件类型白名单、是否含注释与空行）与一条可直接复算的命令 |

## 答辩口径：识别七类为什么只判四类

我们的判断依据只有一条：可机械判定 = 有固定抽取路径 + 断言可落到 `file:line` 或可复现的搜索轨迹。
七类都能识别，是因为识别只需要关键词与句式；四类能判定，是因为它们的证据在仓库里是静态、可枚举、
可复查的事实——路由在不在、测试函数有几个、worker 配成了几、压测文件有没有，命中了能指到行，
没命中能复述查过的类和处数。另外三类（安全、架构、规模）之所以识别但不判，是因为它们要么依赖仓库
之外的运行时与对抗性事实，要么缺少公认的统计口径，硬下结论就变成了猜测。我们宁可把这三类如实
标注为「不判定域」并给出补齐路径，也不制造一个无法复查的结论。
