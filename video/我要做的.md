## §5 口径红线（说错就丢分）

| ❌ 不能说 | ✅ 应该说 |
|---|---|
| Challenger 做完整对抗复核 | Challenger 是**规则版**：换假设重搜（上限 3 轮）+ 只认显式否定反证 |
| Healer / Verifier 已经能用了 | 它们是 **roadmap**；只补观测、不补实现 |
| 定位率 95% / 准确率 90% | 全部 `N=?`，待 5 份需求清单回执后填入，**禁止估算** |
| 部分支持 | 只有三态：`supported` / `contradicted` / `no_evidence`。**"部分支持"只是 `no_evidence` 的一种措辞** |
| 你没做（对 no_evidence 的说法） | 「**我没找到**」——这两句不一样 |
| 我们保证判得对 | 我们保证**轨迹可核**；CI 不保证没 bug，只保证结果可复现 |
| 我们能查所有需求 | 只判 `performance / concurrency / feature / testing` 四类，其余标 `out_of_scope` |
| `gap explain` / `gap deploy` 可以跑 | 只在 **roadmap** 里出现，现场不要敲 |

## §6 可能被追问的 8 个问题（照这个答）

| 问题 | 一句话答法 |
|---|---|
| 你这不就是 lint / 静态分析？ | 静态分析判"代码写了什么"，一条规则就能判；我们判"**能力声称有没有一组证据**"，而该找哪一组要先推演 |
| 判据谁定的？会不会瞎编？ | 判据只能来自：声称自带阈值 / 需求文档 / 事前声明的行业惯例。翻不出来的（"架构合理"）**拒绝生成**，标不可判定 |
| AI 会不会把需求原文抄一遍就当判据？ | 不会，我们加了三层校验：剥离复述、重合率 ≥0.5 判复述、核心词离题检查。真模型 9 条样本实测过 |
| 你凭什么说"没找到"就是真没有？ | 我们不说"你没有"，只说"我查过这几类这几处都没找到"，并且**把查过的清单打印出来**给你去反驳 |
| 漏报率多少？ | `N=?`。漏报和误报**分开报**，这是最容易出丑的地方，所以我们主动划线 |
| 有回执吗？ | 这是 pilot，25 条结论由需求提出人本人判；回执回来才填数，现在全部占位 |
| 同类不是有人做过吗？（SkillTruth） | 做过，且都死了——退化成 AI 面试或简历润色。死因是**站在"查"的立场**，被查的人不配合；我们做的是双方共用的尺子 |
| 码道用到什么程度？ | 需求分析→生成→测试→排错→留痕全流程，D0–D6 连续七天有 md 留痕与截图，不是最后一天补的 |
