# 一页入门：对账引擎（Gap Engine）

> **给一份需求清单和一个代码仓库，输出「要求做的」和「代码里有的」之间的缺口**，每条给定位（`file:line`）或搜索轨迹；查不到的标"没找到"，不沉默。

它服务两种人，用同一把尺子：

- **交差的人**（学生 / 接手的人）：交作业前、被人接手前，看"我还差什么"
- **验收的人**（老师 / 项目负责人）：看"他还差什么"，以及"我查过哪里"

---

## 一、三步跑起来

```bash
cd gap-engine
pip install -e .                                  # 装一次，得到 gap 命令

gap spec   <仓库路径> --spec requirements.md --out 报告.md   # 主模式：需求清单核对
gap analyze <仓库路径> --out 报告.md                          # 副模式：读仓库 README 自检
gap questions <仓库路径> --top 5                              # 只输出"最该被问的 5 个问题"
```

需求清单就是一个 Markdown 列表，一行一条，**不需要额外格式**：

```markdown
# 课程设计要求

- [ ] 支持 Excel 导出
- [ ] 支持 500 并发用户
- [ ] 用户登录
- [ ] 高性能
- [ ] 提供数据可视化
```

---

## 二、报告长什么样（真实产物节选）

```
## 需求可判定性预检
共 5 条需求，4 条可判定，1 条无法验收。
- `requirements.md:6` "高性能" → P95 < 300ms 或 QPS ≥ 500

## 项目实际是什么
- 文件 4 个，代码 63 行
- 入口：app.py
- 依赖：flask, openpyxl
- 一句话：app.py 暴露 2 个路由；依赖 2 个（flask, openpyxl）；0 个测试文件。
- 路由：2 个（GET /export, GET /login）

### 支持 500 并发用户
查过没找到：
- 压测脚本：0 处（扫过 1 处）
- 并发原语：0 处（扫过 1 处）
- worker 配置：0 处（扫过 4 处）
结论：没找到证据（该补）
会被问：「支持 500 并发用户」是在哪份压测脚本和哪种进程/线程配置下测得的？
该补什么：补一个并发压测脚本与结果文件，并说明 worker/线程配置与并发数的对应关系。
- 判据：错误率 < 1% 且 P95 < 1s（行业惯例，需提出人确认）
audit effort：4 类 10 处
```

**读法**：`查到` 是找到的（带 `file:line`），`查过没找到` 是查了但没有的（带"扫过 N 处"），`audit effort` 是这条一共花了多少处检索 —— **报告里的每个数字都能由检索记录复算出来**。

---

## 三、三种结论

| 结论 | 含义 | 你要做的 |
|---|---|---|
| **有证据** | 找到了能支撑的代码/配置/测试，附 `file:line` | 核对这条定位是否真的支撑那句话 |
| **没找到证据** | 查过的地方没有，附完整搜索轨迹 | 要么补上，要么承认这条没做 |
| **有反证** | 找到了与要求相反的代码 | 优先处理；只在能贴出反证时才给 |

> **没有第四种"部分支持"**。含糊的话只会在 reason 里说明，不会造出一个新状态。

---

## 四、它不做什么（边界公开）

- **不判行为契约**：接口是否符合 OpenAPI、请求参数类型 —— 那是 schemathesis / Pact 的活，它不碰。
- **只判四类要求**：性能、并发、功能、测试。架构合理性、规模、安全标 `out_of_scope`，**不进分母**。
- **不替你改代码**：`该补什么` 只给建议和判据，不会生成实现去"圆"结论。
- **不保证判得对，保证轨迹可核**：判据、查过哪里、扫过多少处都写在报告里，你可以自己复跑核对。
- **"没找到"不等于"不存在"**：只说明在它查过的范围内没有。

## 五、三个常见问题

**1. 它说我"没找到证据"，是不是在指控我造假？**
不是。它只说"我查过这些位置，没有找到"，并把查过哪里列出来。你补上一个文件，重跑就会变。

**2. 有些要求它完全判不了？**
会。像"高性能""界面美观"这类翻不出判据的，会进 **需求可判定性预检**，并给出改写建议（如"高性能" → `P95 < 300ms 或 QPS ≥ 500`）。先把它改成可测的，再谈有没有做到。

**3. 能拿它当验收结论吗？**
不能。它是**可复核的起点**：给出定位、轨迹和要追问的问题，最终判定由**需求提出人**做。它的价值是让争议变成"一起看报告"，而不是"你说我说"。
