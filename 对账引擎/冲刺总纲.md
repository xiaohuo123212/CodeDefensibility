## 一、目标与真实约束

**一句话**：输入一份**需求清单**（老师的课程设计要求 / 大创立项要求，或一份自我声称）和一个代码仓库，输出「要求的」和「代码能证明的」之间的缺口；每条给定位（或搜索轨迹）+ 该补什么，查不到的标"未覆盖"，不沉默。

| 约束 | 事实 | 后果 |
|---|---|---|
| 作品提交截止 | **2026-11-20 15:59:59** | 有效开发 **6 天 / 12 人日** |
| 提交频次 | 每天最多 1 次，取**最后一次** | D1 起每天提交 = 免费安全网 |
| 码道使用痕迹 | **硬性核查项**（缺痕或造假＝违规） | **每天归档**，不许 D6 补 |
| 人力 | 2 人（A 引擎 / B 抽取+数据+渲染） | B 是单点瓶颈，物料与沟通都在他手上 |
| 环境 | 码道 IDE 已装、学生认证已过、4000 积分到账 | LLM 成本可控，但仍需实测 |

## 二、已作废与已确立

| 项 | 原值 | 现在 | 原因 |
|---|---|---|---|
| 时间轴 | 14 天（11-15→11-28） | **6 天（11-15→11-20）+ 决赛期** | 原序把部署/视频/PPT 排在提交截止之后 |
| 检查点 | D5 | **D3 中午** | 6 天没有试错空间 |
| 冻结日 | D9 | **D5（11-19）** | 冻结版重跑必须先于提交 |
| 样本 | 10 项目 / 50 条 | **初赛 5 份需求清单 × 5 条 = 25 条，对 5 个项目代码 → 决赛补 10 份 / 50 条** | 回执在 6 天内收不回 10 人；清单回收比"求人标自己"可控 |
| 访谈 | 20 次（D1–D8） | **6 次需求访谈（D1–D3），D3 出 B 端红灯** | 只问一句"哪条要求最难验收"；动机由 deadline 保证，不靠自觉 |
| 指标 | 一次性出 50 条 | **初赛 N≈15 如实标，PPT 写"决赛补齐"** | 主动划线 > 被问出来 |
| 招募话术 | 群发 | **私聊有验收 deadline 的老师 / 项目负责人** | 群发基本没人理 |

**不变的东西（施工图口径，任何压缩都不许动）**：
- 三态只有 `supported / contradicted / no_evidence`，**没有 partial**；
- 断言型必须 `file:line`，搜索型必须 `search_trace`，连轨迹都没有的标 `coverage=none` 但**照样输出**；
- 能力型声称（performance/concurrency）**只有配置无测量 → `no_evidence`**；
- 识别七类、**只判四类**，其余标 `out_of_scope` 不进分母；
- 漏报率与误报率**分开主动报**，绝不合并成"误报"；
- ground truth 由**需求提出人**判（老师 / 项目负责人，三按钮），不是我们自己标；副模式 `--claims` 才由项目作者本人判；
- **样本来源逐份标注**（某课程 / 某大创的原始要求清单）；自己按真实项目反写的只作 demo，**不计入样本、不进任何比率**。

## 三、6 天骨架

| 天 | 日期 | 主线 | 硬验收 |
|---|---|---|---|
| **D0** | 11-14 晚 | 契约包冻结准备 + 3 个 fixture（先 red）+ 约 5 份需求清单 + 成本实测 | 仓库有 schema；已发出邀约 ≥4 份；代码 ≥2 |
| **D1** | 11-15 | 契约冻结会 + Claimer + deps/entry/concurrency/structure | 1 份清单抽 ≥5 条要求，分类抽查 8/10 |
| **D2** | 11-16 | 搜索循环(1 轮) + Matcher 两态 + **轨迹渲染** + 7 抽取器齐 | 1 份清单对 1 个项目→1 份带轨迹报告，数字可算 |
| **D3** | 11-17 | ⭐**检查点 1（12:30）** + 多轮换假设 + contradicted + 需求提出人回执 | "1 份清单→1 份能发出去的 report"；需求访谈累计 ≥4 + B 端红灯判定 |
| **D4** | 11-18 | Challenger + `questions --top` + 5 份清单 × 5 个项目全跑 + 指标脚本 | 25 条结论 + 指标带 N + 回执 ≥4 |
| **D5** | 11-19 | ⭐**冻结 `freeze-v1`** + 重跑 + 前端/部署 + PPT/readme/视频脚本 | 公网链接通；冻结版报告齐 |
| **D6** | 11-20 | 08:00 录视频 → 11:00 交叉验收 → **11:30 提交**（12:00 封版） | 5 目录齐 + 留痕连续 |

**撤退线（触发即执行，不临场讨论）**：D3 端到端不通 → 只做 `performance`+`testing`、4 份清单、全规则版，改称"规则版 pilot"；回执 <3 → 转现场判定；部署失败 → 本地一键 + 录屏；积分不够 → Matcher/抽取器全规则化。

## 四、vibecoding 的质量底线：5 道闸门

| 闸门 | 是什么 | 防什么 |
|---|---|---|
| **G0 契约包** | D1 上午冻结 `schema.py` + 三态表 + "契约十句"，所有 AI 会话 prompt 以它开头 | AI 各自发明字段、偷偷加第四态 |
| **G1 fixture 回归** | 3 个 <40 行的微型仓库，`pytest -q` 20 秒跑完，红灯不许合并 | 改坏主路径 |
| **G2 表驱动测试** | 三态判定表 → 9 个 parametrize 情形 | 判定规则被绕过 |
| **G3 可算性断言** | "4 类 11 处" 必须等于 `len(trace)/sum(scanned)` | AI 在报告里编漂亮数字 |
| **G4 人眼抽查** | 每天 5 条，人指 `file:line` 核一眼 | 结论错但代码"看起来对" |

**合流纪律**：每天 12:30 / 19:00 两次，合流必跑 G1+G2+G3 + G4 抽 5 条。

## 五、招募：从指标反推人

25 条要求的配额：`concurrency` 6 / `performance` 6 / `feature` 7 / `testing` 6。
→ **每份清单至少贡献 1 条 performance 或 concurrency**，所以这 5 份清单要挑**老师明确写了量化要求**的（"支持 XX 并发"/"响应 < XX ms"）。

**金标准**：不找最熟的、不找最强的，找**"要求提得比代码大"的那个人**——他的那几条要求正是评委要问的。

| 层 | 画像 | 人数 | 用途 |
|---|---|---|---|
| P0 | 有验收 deadline（课程设计验收 / 大创中期检查） | 3–4 | 主样本 + B 端动机数据 + 最好证言 |
| P1 | 手上有多条量化要求的课程/项目 | 1–2 | 凑满 4 类配额 |
| P2 | 仓库主人（副线 `--claims`） | 2–3 | 回执收不回时的现场判定池 |

**不可删的一句**："尤其如果它说错了，一定告诉我哪错了。"
**催收必带**："你要是不方便我换个人也行。"

## 六、指标与答辩口径（初赛版）

| 指标 | 目标 | 备注 |
|---|---|---|
| 需求提出人认可率 | ≥70%（N≈15） | N 如实写，PPT 标"决赛补齐至 50" |
| 定位率 | ≥90% | 分母＝断言型结论，最站得住 |
| 漏报率 | ≤20%，主动报 | 与误报分开 |
| 误报率 | ≤10%，主动报 | 同上 |
| 无法证伪异议 / 说不清 / 未覆盖 | 如实报，不设目标 | 主动报边界是加分项 |

**PPT 必须有的一页**："我们不能证明什么"——pilot、5 份需求清单 + 5 个项目 / 25 条、有效回执 N≈15、只判四类、限 Python/JS、500–5000 行。
